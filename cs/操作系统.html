操作系统 Operating System

人话讲解

操作系统是硬件和应用程序之间的中间人。它管理 CPU、内存、磁盘、网络——让 100 个程序同时跑而不打架。

理解 OS 才能真正写出高性能的并发代码。你以为的「同时执行」其实是 OS 在背后疯狂切换。

「An operating system is a collection of things that don’t fit into a language. There shouldn’t be one.」— Dan Ingalls

进程 Process

进程 = 运行中的程序。有独立的地址空间、文件描述符、信号处理。

fork() — Unix 的魔法

fork 之后：子进程复制父进程的地址空间（COW 优化），但各自独立。

线程 Thread

线程 = 进程内的执行流。同一进程的线程共享地址空间，但各有自己的栈和寄存器。

进程线程
创建开销大（复制地址空间）小（共享地址空间）
通信IPC（管道、消息队列、共享内存）共享变量
隔离性强（一个崩不影响其他）弱（一个崩全进程崩）
上下文切换重（切换页表）轻（不用切换页表，但 TLB 要刷）

线程的并发问题

CPU 调度 Scheduling

调度器回答的问题：就绪队列里那么多进程，先跑谁？

调度算法对比表

算法思想优点缺点适用
FCFS 先来先服务按到达顺序公平、实现简单convoy 效应：长任务堵住短任务批处理
SJF 最短作业优先先跑最短的平均等待时间最优需要预知运行时间；长任务饿死理论最优
SRTF（SJF 抢占版）新到的更短就抢占平均等待最优（可抢占时）同上理论
RR 时间片轮转每人一个时间片 q响应快、公平q 太小切换开销大；q 太大退化成 FCFS交互式（默认）
优先级 Priority优先级高的先跑灵活低优先级饿死 → 用老化 Aging 解决实时/分级
多级反馈队列 MLFQ多队列 + 动态降级兼顾响应与吞吐参数难调现代 OS 主流思路

关键指标：

  • 周转时间 Turnaround = 完成时间 − 到达时间
  • 等待时间 Waiting = 周转 − 运行时间
  • 响应时间 Response = 第一次被调度 − 到达

例题：三个进程同时到达，运行时间分别为 A=24, B=3, C=3，算平均等待时间。

解题思路：① 同时到达 → SJF 平均等待最短，直接按运行时间排序；② 不同时到达 → 画甘特图逐事件推进；③ RR 的响应时间 = 到达到第一次被调度。

FCFS 顺序 A,B,C：  等待 = 0, 24, 27 → 平均 17
SJF 顺序 B,C,A：   等待 = 0, 3, 6   → 平均 3   ← 最优
RR q=4：A 跑 4 → B 跑 3 → C 跑 3 → A 继续 ...
         等待 = 0, 4, 7              → 平均 ~3.7

MLFQ 规则：① 新进程进最高优先级队列；② 用完时间片没完成 → 降一级；③ 主动让出 CPU（I/O）→ 不降级；④ 定时把所有进程升回最高级（防饿死）。

同步 Synchronization

互斥锁 Mutex

信号量 Semaphore

控制最多 N 个线程同时访问资源。

Mutex vs Semaphore：互斥锁是「一个人用」，信号量是「最多 N 个人用」。互斥锁可以理解为信号量 N=1 的特例，但互斥锁有所有者概念（谁锁谁解），信号量没有。

死锁 Deadlock

四个必要条件（缺一不死锁）

  1. 互斥 — 资源不能共享
  2. 持有并等待 — 拿着锁等另一个锁
  3. 不可抢占 — 不能抢别人的锁
  4. 循环等待 — A 等 B，B 等 C，C 等 A

预防：固定加锁顺序（所有人先 lock1 再 lock2）。

银行家算法 Banker’s Algorithm

思路：银行家不借出可能导致自己破产的钱。分配资源前检查是否存在安全序列——按某个顺序执行所有进程，每一步都有足够资源完成。

数据结构：Available（可用资源）、Max（每个进程最多要）、Allocation（已分配）、Need = Max − Allocation。

例题：系统有 10 台打印机，三个进程：

        Max   Allocation   Need
P0       8        3          5
P1       6        2          4
P2       4        2          2
Available = 3

解题思路：① 算 Need；② 循环找「Need ≤ Available」的进程，模拟它完成并回收全部资源；③ 全部能完成 → 安全；卡住 → 不安全，拒绝本次分配。

找 Need ≤ Available=3 的进程：P2 (2 ≤ 3) ✅ → 假设 P2 先跑完，释放 2+2=4 → Available = 7
此时 P0 (5 ≤ 7) ✅ → 跑完释放 3 → Available = 10；P1 (4 ≤ 10) ✅
安全序列：P2 → P0 → P1（或 P2 → P1 → P0）。系统处于安全状态。

内存管理 Memory Management

虚拟内存 Virtual Memory

每个进程看到的是自己的虚拟地址空间，OS + MMU 负责映射到物理内存。

虚拟地址 ──▶ [页表 Page Table] ──▶ 物理地址

好处：

  • 隔离：进程 A 访问不到进程 B 的内存
  • 更大的地址空间：可以用磁盘当内存（swap）
  • 共享：同一份代码（如 libc）多进程共享

分页 Paging

把内存切成固定大小的页 Page（通常 4 KB）。

虚拟地址：[页号 | 页内偏移]
              │
              ▼
        页表 Page Table
              │
              ▼
物理地址：[帧号 | 页内偏移]

分页 vs 分段

分页 Paging分段 Segmentation
划分方式固定大小（4KB）按逻辑意义（代码/数据/栈）
外部碎片无（页帧固定）有
内部碎片有（最后一页不满）无
地址结构页号 + 页内偏移段号 + 段内偏移
按段共享困难容易
现代系统Linux/Windows 用分页早期 OS 用

TLB — 快表

页表在内存里，每次访存都要查页表 → 又慢一次。TLB 是页表项的硬件缓存（在 MMU 里），命中则一次访存搞定。

虚拟地址 → [TLB 命中?] → 物理地址（~1 cycle）
             ↓ 未命中
          查页表（内存，~100+ cycles）→ 更新 TLB

局部性让 TLB 命中率 > 99%：程序总是集中访问少数几个页面。上下文切换会刷 TLB——这就是线程切换比进程切换便宜的原因之一。

页面置换算法

内存满了要换出页面，换哪个？

算法策略优缺点
FIFO换最早的简单，但 Belady 异常（加大内存反而缺页更多）
LRU换最久没用的近似最优，但实现成本高
Clock环形扫描 + 引用位LRU 的工程近似 ✅

缺页 Page Fault：访问的页不在内存 → 缺页中断 → 从磁盘读入 → 若内存满先换出。缺页率 × 磁盘延迟（毫秒级）是性能杀手——所以「顺序访问大文件」比「随机访问」快几个数量级。

文件系统 File System

核心概念

inode：存文件的元数据（大小、权限、数据块指针）
目录：文件名 → inode 的映射
超级块 Superblock：文件系统的元信息

Unix 文件系统的经典设计

硬链接 vs 符号链接：硬链接共享 inode（删原文件还在，不能跨文件系统、不能链接目录）；符号链接是「路径的快捷方式」（原文件删了就失效，可跨文件系统）。

进程间通信 IPC

方式特点速度/方向
管道 Pipe单向，父子进程间慢，字节流
命名管道 FIFO有文件名，无亲缘关系的进程也可用慢，字节流
消息队列有类型的消息，异步中，有界
共享内存最快（无拷贝），但需同步最快，双向
Socket可跨网络，最通用中，双向
信号 Signal异步通知（SIGKILL, SIGTERM, SIGCHLD…）极轻量，只传信号

选型：同机大量数据 → 共享内存；少量结构化消息 → 消息队列；跨机器 → Socket；父子进程简单单向 → 管道。

二级结论速查

  1. SJF 平均等待最优但现实中不可实现（不知道运行时间）→ MLFQ 是工程答案
  2. 死锁三招：预防（破坏四条件之一）、避免（银行家算法）、检测+恢复（资源分配图找环）
  3. 虚拟内存的关键：页表让「地址空间」和「物理内存」解耦，进程以为独占内存
  4. TLB + 缓存：两次「假装很快」的硬件缓存，靠的都是局部性
  5. 上下文切换：线程 < 进程（不用换页表，但 TLB 都要刷）
  6. 银行家算法是「悲观的安全检查」：宁可拒绝，不让系统进入不安全状态

常见坑

  1. fork 后忘记处理僵尸进程 → waitpid() 或 SIGCHLD handler
  2. 多线程共享变量不加锁 → 数据竞争，结果随机
  3. 死锁 — 加锁顺序不一致是万恶之源
  4. OOM Killer — 内存不够时 Linux 随机杀进程，别让内存 leak
  5. mmap vs read — mmap 省一次拷贝但 page fault 有开销
  6. 信号量当互斥锁用 — 语义不同，信号量没有所有者，容易解锁错乱
