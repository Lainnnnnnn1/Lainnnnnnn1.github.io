编程语言理论 Programming Language Theory

人话讲解

你天天写 Python/Rust/JavaScript——但你想过没有，这些语言本身是怎么被定义的？为什么有些语言「安全」、有些「快」、有些「表达力强」？

编程语言理论（PLT）从数学的角度研究：「什么叫一段程序？」「怎么保证程序不会出错？」「两个程序是不是等价的？」

「A language that doesn’t affect the way you think about programming is not worth knowing.」— Alan Perlis

λ 演算 Lambda Calculus

λ 演算是编程语言的「汇编」——一切计算都可以归约为 λ 演算。

三条基本规则

β-归约

Church 编码：甚至不需要数字——纯 λ 就能表示一切数据。

0 := λf. λx. x
1 := λf. λx. f x
2 := λf. λx. f (f x)

类型系统 Type System

类型系统 = 给程序加标签，在运行前就能发现某些错误。

类型系统的维度

静态 vs 动态：什么时候检查类型？
├── Static (编译期)：Rust, Haskell, TypeScript, Java
└── Dynamic (运行期)：Python, JavaScript, Ruby

强 vs 弱：允不允许隐式类型转换？
├── Strong：Python（"1" + 1 → TypeError）
└── Weak：JavaScript（"1" + 1 → "11"）

显式 vs 隐式：要不要写类型标注？
├── Explicit：Java (int x = 1;)
└── Implicit：Haskell, OCaml (类型推导)

多态 Polymorphism

Hindley-Milner 类型推导

ML 系语言（Haskell, OCaml, Rust）的杀手特性——不写类型标注，编译器自动推导。

编程范式

面向对象 OOP

核心概念：
├── 封装 Encapsulation：数据和操作绑在一起
├── 继承 Inheritance：子类复用父类代码
├── 多态 Polymorphism：同一接口不同实现
└── 抽象 Abstraction：隐藏细节，只暴露接口

函数式编程 FP

核心思想：
├── 纯函数：相同输入永远返回相同输出，没有副作用
├── 不可变性 Immutability：数据创建后永不修改
├── 高阶函数：函数可以作为参数和返回值
├── 声明式：说"做什么"，不说"怎么做"
└── 引用透明：表达式可以被其值替换而不改变程序行为

范式对比

OOPFP
核心单元对象 (数据+行为)函数
数据可变不可变
复用继承/组合高阶函数/组合子
副作用常见避免
并发难（共享状态）易（无共享）
代表语言Java, C++, PythonHaskell, OCaml, Elixir

编译 vs 解释

编译 Compilation：源代码 → 编译器 → 机器码 → 执行
解释 Interpretation：源代码 → 解释器 → 直接执行（逐行）

JIT (Just-In-Time)：运行时把热点代码编译成机器码
编译型解释型JIT
启动速度慢快中
运行速度最快慢接近编译型
代表C, Rust, GoPython, RubyJava(JVM), JS(V8), C#

数学连接

  • λ演算 — 编程语言的数学基石，图灵完备
  • 类型论 — 命题即类型，程序即证明（Curry-Howard 同构）
  • 范畴论 — 函数式编程的深层数学结构（Monad, Functor, Applicative）
  • 自动机理论 — 正则表达式、上下文无关文法 → 词法/语法分析
  • 形式语言 — Chomsky 层级：正则 → 上下文无关 → 上下文相关 → 递归可枚举

常见坑

  1. 图灵完备 ≠ 好用 — Brainfuck 也是图灵完备的
  2. 动态类型 ≠ 不需要类型思维 — 写出 "1" + 1 = "11" 的人没搞懂隐式转换
  3. OOP 不是银弹 — 滥用继承导致「香蕉问题」（想要个香蕉，却得到了拿香蕉的猩猩和整片丛林）
  4. Monad 恐惧 — Monad 其实就是「可组合的计算」，别被数学名词吓到
