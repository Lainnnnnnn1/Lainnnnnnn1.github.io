编译器 Compiler

人话讲解

编译器是程序员的终极「翻译官」——把人能读懂的源代码翻译成机器能执行的指令。你写 x = a + b * c，编译器要理解：这是什么类型的变量？乘法优先于加法吗？对应哪条 CPU 指令？

编译器不是黑魔法。它是一系列定义明确的阶段，每个阶段做一件事，输入和输出都有清晰的结构。

「Don’t be proud of writing a compiler. It’s the lowest level of programming. Be proud of writing one that people actually use.」— 匿名

数学连接

  • 自动机理论 — DFA/NFA → 词法分析；PDA → 语法分析
  • 形式语言 — Chomsky 层级：正则语言（Lex）→ 上下文无关（Parse）
  • 图论 — AST 是树，寄存器分配的干涉图，控制流图
  • 数理逻辑与集合论 — 类型系统建立在逻辑基础上
  • 抽象代数 — 格论（Lattice Theory）用于数据流分析

常见坑

  1. 左递归 — LL 解析器碰上左递归会无限循环：expr ::= expr + term
  2. 悬空 else — if a if b x else y — else 匹配哪个 if？
  3. 类型系统的边界 — 类型安全 ≠ 正确（可以编译通过但有逻辑 bug）
  4. 优化改变语义 — volatile、内存序：过度优化能破坏并发代码
  5. UB (Undefined Behavior) — C/C++ 编译器会利用 UB 做「惊喜优化」
