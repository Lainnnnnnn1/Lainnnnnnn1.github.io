计算机体系结构 Computer Architecture

人话讲解

计算机体系结构 = 计算机硬件怎么设计的。从晶体管到 CPU 到内存到总线——这一层决定了软件能跑多快的根本上限。

写 C 和写 Python 的人都需要理解缓存——因为 cache miss 的性能惩罚能差 100 倍。

核心思想：程序和数据存在同一个内存里。这是今天几乎所有计算机的架构。

冯·诺依曼瓶颈：CPU 和内存之间的带宽限制。CPU 越来越快，内存跟不上 → 内存墙。

CPU 核心概念

指令周期 Instruction Cycle

取指 Fetch → 译码 Decode → 执行 Execute → 访存 Memory → 写回 Writeback

RISC vs CISC

RISC (ARM, RISC-V)CISC (x86)
指令长度定长（32-bit）变长（1~15 字节）
指令数量少，简单多，复杂
寻址模式Load/Store 架构，只有 load/store 访存可内存直接操作（add mem, reg）
复杂指令实现编译器组合简单指令微码 Microcode 解释
硬件简单、省电、流水线友好复杂、功耗高
代表ARM, RISC-V, MIPSx86, x86-64

为什么 RISC 赢了移动时代：指令简单 → 硬件简单 → 省电；定长指令 → 取指译码简单 → 流水线深度可以拉得很高。而现代 x86 靠内部把复杂指令翻译成微操作 µops 来假装自己是 RISC——今天的 Intel/AMD 本质是「CISC 外壳 + RISC 内核」。

流水线 Pipelining

没有流水线：
[取指|译码|执行|访存|写回] → [取指|译码|执行|访存|写回] → ...
                      指令1                              指令2

有流水线（理想）：
取指 | 译码 | 执行 | 访存 | 写回
     取指  | 译码  | 执行 | 访存 | 写回
           取指  | 译码  | 执行 | 访存 | 写回

五级经典流水线：IF（取指）→ ID（译码）→ EX（执行）→ MEM（访存）→ WB（写回）。理想情况下每周期完成一条指令，吞吐量提升约 5 倍（单条指令延迟不变，但吞吐大增）。

流水线冒险 Pipeline Hazards

  1. 数据冒险 Data Hazard — 后一条指令依赖前一条的结果
  2. 控制冒险 Control Hazard — 分支跳转导致取错指令
  3. 结构冒险 Structural Hazard — 两条指令抢同一个硬件

解决办法：

冒险解决手段代价
数据冒险转发 Forwarding/Bypassing（EX 阶段结果直接送回 ALU 输入）硬件成本，零延迟
数据冒险（load-use）停顿 Stall/Bubble（插入 NOP）1~2 个周期
控制冒险分支预测 + 预测错误时 flush预测错损失 10~20 个周期
结构冒险指令缓存和数据缓存分离、端口复制面积

分支预测：静态（永远预测不跳）→ 动态（2-bit 饱和计数器，记录上次跳转历史）→ 现代 TAGE 等预测器准确率 > 95%。预测错误的代价 = 流水线深度 × 周期，所以深流水线 CPU 特别怕乱序分支。

缓存的核心思想：时间局部性 & 空间局部性。

  • 时间局部性 Temporal Locality：刚访问的数据很可能再被访问
  • 空间局部性 Spatial Locality：刚访问的数据附近的数据很可能被访问

每一层都是上一层的缓存：寄存器是 L1 的缓存，L1 是 L2 的缓存……「缓存」是计算机里最通用的设计模式。

缓存映射方式

方式描述冲突概率
直接映射 Direct Mapped每个内存块对应唯一缓存行高
全相联 Fully Associative可放任意位置零（但硬件成本高）
组相联 Set AssociativeN 路组相联 → 折中方案中

地址拆分（直接映射/组相联）：

内存地址 = [ Tag | Set Index | Block Offset ]
  • Block Offset：块内偏移（块大小 64B → log₂64 = 6 bit）
  • Set Index：决定去哪个组找（组数 S → log₂S bit）
  • Tag：剩下的高位，用来确认组里那一行是不是要找的块

例题：64KB 缓存，4 路组相联，块大小 64B，32-bit 地址，问 Tag / Index / Offset 各多少位？

解题思路：① 组数 = 缓存大小 ÷ (路数 × 块大小) = 64KB ÷ (4 × 64B) = 256 组；② Offset = log₂64 = 6 bit；③ Index = log₂256 = 8 bit；④ Tag = 32 − 8 − 6 = 18 bit。

命中率排序：全相联 ≥ 组相联 ≥ 直接映射；硬件成本反过来。替换策略：LRU（组相联常用）、FIFO、随机。

性能公式 Performance

核心公式（考试必背）：

CPU 时间 = 指令数 IC × 每指令周期数 CPI × 时钟周期时间 T
        = IC × CPI / 时钟频率 f

三个因素的权衡：

  • IC：指令集设计（CISC 指令少但复杂，RISC 指令多但简单）
  • CPI：流水线效率、缓存命中率、分支预测准确率
  • T：工艺（7nm vs 5nm）、时钟频率

例题：程序有 2×10⁹ 条指令，平均 CPI = 1.5，时钟频率 3 GHz。

  • CPU 时间 = 2×10⁹ × 1.5 / (3×10⁹) = 1.0 秒
  • 若优化缓存使 CPI 降到 1.2 → 时间 = 2×10⁹ × 1.2 / 3×10⁹ = 0.8 秒（省 20%）

Amdahl 定律：

加速比=(1−p)+p/s1​

p 是可加速部分占比，s 是加速倍数。p 很小的时候，s 再大也没意义——先优化占比大的部分。

补码 Two’s Complement

负数 = 按位取反 + 1。这样 x + (-x) = 0 自然成立，且只有一种零。加法和减法共用同一个电路，这就是补码被选中的原因。

MIPS 是经典教学 ISA（RISC）。三种格式：R 型（寄存器运算）、I 型（立即数/访存/分支）、J 型（跳转）。

二级结论速查

  1. 理想 CPI = 1：流水线每周期完成一条指令；冒险和 cache miss 把 CPI 拉高
  2. 缓存命中率 vs 加速：miss 代价是 100 周期量级，命中率 99% 比 95% 快 4 倍以上
  3. 局部性是一切缓存设计的根基：时间局部性 → LRU；空间局部性 → 预取、大块
  4. RISC vs CISC 已合流：现代 x86 内部翻译成 µops，ARM 也在加复杂指令
  5. Amdahl 定律：先优化占比大的部分
  6. 补码：加减同一电路、只有一种零，所以硬件简单

数学连接

  • 布尔代数 — 数字电路、逻辑门的基础
  • 线性代数 — 矩阵乘法是 GPU/TPU 的核心操作，SIMD 的本质
  • 数值分析 — 浮点误差分析、数值稳定性
  • 模运算 — 补码、哈希、校验和

常见坑

  1. 忘记字节序 — Big Endian vs Little Endian，网络字节序是大端
  2. 内存对齐 — struct 有 padding，sizeof(struct) 可能 > 成员之和
  3. 缓存行伪共享 False Sharing — 多线程写相邻变量，互相 invalidate 缓存行
  4. 分支预测失败代价 — 热路径里尽量避免不可预测的 if
  5. 把 cache 当 RAM 用 — 缓存是硬件自动管理的，你只能写「友好」的代码
  6. 浮点直接 == 比较 — 永远用 epsilon 容差
